# GMX Market — مارکت‌پلیس گیمینگ وردپرس

پروژه اختصاصی فروش آیتم، جم، اکانت و خدمات گیمینگ (مشابه eldorado.gg / g2g) شامل **قالب اختصاصی** + **افزونه موتور مارکت‌پلیس** — بدون هیچ افزونه ثالث، بدون صفحه‌ساز.

---

## ساختار پروژه

```
├── gmx-market/          ← افزونه موتور (سفارش، چت، تیکت، کیف پول، پرداخت، پیامک)
│   ├── gmx-market.php   نقطه ورود
│   ├── includes/        کلاس‌ها (Orders, Chat, Tickets, Wallet, Payments, Notify, Uploads, Dashboard, Seller, Settings, Install, Post_Types)
│   ├── templates/       قالب‌های داشبورد کاربر
│   └── assets/          CSS/JS داشبورد
├── gmx-theme/           ← قالب اختصاصی وردپرس (دارک، RTL، فارسی)
│   ├── style.css        هدر قالب
│   ├── front-page.php   صفحه اصلی (هیرو + دسته‌ها + محصولات + مراحل خرید)
│   ├── single-gmx_product.php  صفحه محصول + فرم سفارش
│   └── assets/css/main.css     دیزاین سیستم قالب
└── tools/lint-php.js    ← لینتر سینتکس PHP (Node، بدون نیاز به PHP)
```

## نصب

1. **افزونه**: پوشه `gmx-market` را در `wp-content/plugins/` قرار دهید و فعال کنید. جداول دیتابیس، نقش فروشنده و صفحات `داشبورد` و `تسویه حساب` خودکار ساخته می‌شوند.
2. **قالب**: پوشه `gmx-theme` را در `wp-content/themes/` قرار دهید و فعال کنید.
3. در پیشخوان → **تنظیمات → پیوندهای یکتا** یک‌بار روی «ذخیره» بزنید (برای فعال‌شدن rewrite rules داشبورد و فایل‌ها).
4. صفحه اصلی را روی «یک برگه ثابت» تنظیم کنید تا `front-page.php` نمایش داده شود.

## پیکربندی (پیشخوان → گیمینگ مارکت)

| بخش | تنظیمات |
|---|---|
| عمومی | واحد پول، درصد کمیسیون فروشنده (پیش‌فرض ۵٪) |
| پرداخت | انتخاب درگاه: **زرین‌پال / IDPay / PayPing** + کلید API |
| پیامک و ایمیل | **کاوه‌نگار / ملی‌پیامک**، شماره مدیر، دسته‌بندی‌های تیکت |

## جریان سفارش (اسکرو)

```
ثبت سفارش → pending_payment → پرداخت آنلاین/کیف پول → paid
→ فروشنده/پشتیبان: processing → delivered (ثبت اطلاعات تحویل)
→ خریدار تایید → completed → تسویه خودکار به کیف پول فروشنده (منهای کمیسیون)
```

- هر تغییر وضعیت: ثبت در **تاریخچه** + پیامک + ایمیل + نوتیف داخلی.
- اگر محصول «تحویل خودکار» داشته باشد، بلافاصله پس از پرداخت اطلاعات به خریدار نمایش داده و سفارش delivered می‌شود.
- بازپرداخت → وجه به **کیف پول خریدار** برمی‌گردد.
- انتقال‌های نامعتبر وضعیت (مثلاً completed → pending) در سطح کلاس مسدود است.

## چت داخلی

- گفتگو با هر سفارش پرداخت‌شده **خودکار** ساخته می‌شود (خریدار ↔ فروشنده).
- ارسال متن + فایل (jpg/png/webp/gif/pdf/zip/txt تا ۴ مگ) با REST API.
- Polling هر ۴ ثانیه، شمارنده پیام خوانده‌نشده، تیک خوانده‌شدن.
- فایل‌ها **خارج از پوشه عمومی آپلود** و فقط برای طرفین سفارش/تیکت سرو می‌شوند (`/gmx-file/{key}`).

## تیکت

- دسته‌بندی قابل تنظیم، پیوست فایل، وضعیت (باز/پاسخ داده شده/در انتظار کاربر/بسته).
- پاسخ پشتیبان → ایمیل به کاربر.

## REST API (افزونه)

| مسیر | متد | توضیح |
|---|---|---|
| `/wp-json/gmx/v1/chat/messages?chat_id=&after_id=` | GET | پیام‌های جدید (polling) |
| `/wp-json/gmx/v1/chat/send` | POST | ارسال پیام (multipart: body, file) |
| `/wp-json/gmx/v1/chat/seen` | POST | علامت‌گذاری خوانده‌شده |

احراز هویت: کوکی + `X-WP-Nonce` (خودکار در JS افزونه).

    $fields['server'] = array( 'label' => 'سرور', 'required' => true );

## جدول‌های دیتابیس

## نقش‌ها

- `gmx_seller` — فروشنده گیمینگ (ثبت محصول پس از تایید مدیر، مدیریت فروش‌ها، برداشت)
- مدیر: تغییر وضعیت همه سفارش‌ها، بررسی برداشت‌ها (`GMX_Wallet::decide_withdrawal`)

## سرعت و بهینه‌سازی

- بدون jQuery، بدون صفحه‌ساز — JS خالص (~۷KB) و CSS سبک.
- اسکریپت‌ها فقط در صفحات داشبورد لود می‌شوند (register → enqueue مشروط).
- تصاویر lazy، سایزهای اختصاصی (`gmx-card`, `gmx-hero`).
- CSS متغیرمحور با Dark theme و RTL کامل؛ برای LCP زیر ۲ ثانیه، کش صفحه (LiteSpeed/Redis) و CDN تصاویر توصیه می‌شود.

## نکات استقرار (Production)

1. SSL اجباری + `WP_REDIS` برای object cache.
2. Cron واقعی جای wp-cron برای صف پیامک.
3. محدودیت آپلود PHP را با `gmx_chat_upload_max` هماهنگ کنید.
4. بکاپ روزانه دیتابیس + پوشه `uploads/gmx-private`.
